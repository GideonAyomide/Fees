3. Root Cause Analysis: What Actually Causes the 2-to-3 Second Delay?
-----------------------------------------------------------------------------
In class, validation was observed adding a 2 to 3 second delay on signup.
Our benchmark proves that Zod schema validation itself takes 0.03 ms. The observed delay is NOT schema validation.

The 2-to-3 second latency occurs when developers place external synchronous operations into the validation lifecycle:
1. Outbound Network Roundtrip: Calling an external breach API (e.g. HaveIBeenPwned API) synchronously inside the request lifecycle adds 800ms - 2200ms depending on internet latency and TLS handshake.
2. Synchronous SMTP Handshake: Attempting to connect to an external mail server synchronously inside the registration handler adds 1500ms - 3000ms.
3. Database Cold Connection: Cold pooling / connection establishment to remote PostgreSQL.

Remedy Applied in Crown Heights Academy Architecture:
- Schema boundary validation runs first in-memory (taking < 2 ms).
- Invalid requests fail immediately without touching database or external APIs.
- Breached password checks use a fast k-anonymity prefix cache and a 5-second timeout fallback.
- Email delivery is completely detached from the HTTP request into a background job (Step 10).
